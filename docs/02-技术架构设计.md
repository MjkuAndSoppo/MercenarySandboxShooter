## 3. 关键系统设计

### 3.1 阵营与队伍
- `Faction` 枚举（LONESTAR/VALKYRA/MANTICORE）+ 服务端同步的 `FactionManager`。
- 计分板队伍承载：名字染色、友伤禁止、Tab 排序。玩家加入即设 `team` 与 `faction` 附体。
- 人数动态平衡：每 30s 结算一次各阵营人数，最少方获得赏金系数（1.1x）。

### 3.2 控制区 / Hot Zone（服务端权威）
- `ControlZone`：圆心坐标 + 半径 + 归属性 + 冷却计时；`ServerTickHandler` 驱动 30s 结算。
- 计数规则：结算瞬间取圈内存活玩家按阵营聚合，Hot Zone 内 ×2 权重。
- **区块未加载问题（重要）**：控制区可能落在未加载区块 → 设计为「逻辑区」而非依赖实体扫描：用玩家坐标查询（即使区块卸载，玩家所在区块必加载），并以 `SectionPos` 圈内坐标判定，避免全图 chunk 强制加载。结算若 0 人在圈 → 不加分。
- Hot Zone 每 45s 迁移：在控制区内取随机点，倾向人数劣势侧。

### 3.3 塔楼与钻井台
- 塔楼 = 方块 + BlockEntity：交互出码字（服务端生成，客户端展示）、码字进度存储于队伍数据。
- 钻井台 = BlockEntity 运行态：燃料（物品）随时间消耗，生效期间每 tick 把控制区圆心向 FOB 偏移；全图广播提示。

### 3.4 经济与配装
- 现金：`DataAttachment`（int）挂 `ServerPlayer`，仅服务端可改；同步走附体同步。
- 交易服务 `EconomyService`：`trySpend(player, cost)` / `pay(player, amount, reason)`，统一走日志与防外挂校验。
- 配装：背包内物品带 `DataComponent`（负重、属性）。负重由服务端累计，超阈值给移速/跳跃修正（AttributeModifier）。
- 死亡：`LivingDropsEvent` 拦截，掉落配装、保留现金；保险券（P1）抵扣掉落。

### 3.5 建造与破坏
- 工事方块：自定义 `Block`（mapColor/破坏时间/硬度），绑定耐久 `BlockEntity`；PvP 破坏走专用伤害事件（区分玩家/环境），归属队伍记录在方块附体。
- 建造权限：仅 FOB 一定半径内可放置；放置时从队伍金库扣费（金库 = 队伍侧账户，见 §3.6）。
- 摧毁结算：按工事等级给击杀者/队伍发赏金；己方拆除回收 50%。

### 3.6 队伍金库与服务器侧账户
- 工事/塔楼费用从**队伍金库**扣，个人现金可向金库转账（WARDOGS 的团队经济感）。金库 = 服务端 `TeamAccount` 数据。

### 3.7 HUD 与菜单（UI 技术选型）

- **P0 默认：NeoForge 原生 `GuiGraphics` / `Screen` 自绘** —— HUD 覆盖层与全部菜单（阵营选择/配装商店/建造目录）用原生渲染 API 实现，零额外 UI 依赖；原型 tech-dark 视觉稿（矩形贴图/等宽字体）原生即可还原，无需重 UI 框架。
- HUD 覆盖层（客户端）：计分板（三方分数/进度条）、30s 结算倒计时、Hot Zone 圈内标记、现金、负重条、击杀流。全部走 `RenderGuiEvent`/自定义 HUD 类，配置项可开关。
- **可选增强（按需引入，不进 P0 核心）**：
  - Cloth Config API：Mod 设置页（实体距离引导、HUD 开关、键位）。
  - JEI：物品图鉴 / 商店物品展示（玩家友好）。
  - Patchouli：玩法手册 / 教程文档。
  - 3D 展示：GeckoLib 动画模型在商店/结算界面做武器/工事预览（P1，随动画实体立项）。
- **明确排除**：ImGui / CEF / HTML 等重 UI 框架 —— 与 MC 渲染管线冲突、包体积大、HUD 帧率差，本项目无此需求。
- **性能**：HUD 元素缓存布局与纹理（避免每帧字符串布局/分配）；世界空间标记（IFF 三角标、标记点、Hot Zone 圈）用批量 quad 绘制、不做每帧实体遍历；所有 HUD 元素可开关。

### 3.8 性能（30 人 + AI 等效 60~80 战斗单位）
- 避免每 tick 全图实体扫描；控制区用坐标判定。
- 抛射物限流（每玩家每秒投射物数上限），粒子/音效客户端节流。
- 网络节流：位置类高频包用 `Entity` 原生同步；自定义状态包降频（≥2 tick 间隔）。
- 推荐服务端：Paper 化优化不适用（NeoForge），用性能向 mod 组合（见 03 文档「配套性能 mod」）。

### 3.9 远距玩家渲染与可见性（Known Issue）

- **现象**：大地图战场上，视距内的远处玩家不渲染 → 狙击、侦察、控局判断受损（WARDOGS 核心体验的一部分）。
- **根因（三类）**：
  1. 客户端「实体距离」（Entity Distance，1.19.3+）滑块低于区块视距，实体按模拟距离比例被裁剪。
  2. 第三方性能 mod（EntityCulling / 实体剔除类）做视锥 + 遮挡剔除，远处玩家实体被剔除。
  3. 服务端 simulation distance 与客户端 render distance 不匹配：远端玩家所在区块客户端未加载 → 不渲染（属渲染距离外，体验同源）。
- **解决与缓解**：
  - **P0 配置引导**：Mod 启动时引导「实体距离 = 最大」；检测到 EntityCulling 类 mod 时提示把玩家实体加入剔除白名单（发布页 FAQ 写入兼容矩阵）。
  - **P0 视觉兜底**：对玩家实体放宽名字标签渲染距离 + 阵营染色标签 —— 即使小人未渲染也能定位。
  - **P1 玩法替代（推荐，符合 WARDOGS）**：标记系统（快捷键标记敌方位置，标记点全图可见、持续 N 秒）+ 雷达塔/塔楼区域探测圈 —— 远距交战不依赖像素级渲染。
  - **P1 渲染兜底**：Mixin 对玩家实体豁免视锥剔除并设距离分级（远距降为名称标记/低模），仅玩家数超阈值时启用分级。
  - **兼容矩阵**：Sodium/Embeddium（分级渲染）、EntityCulling（白名单）、FerriteCore（无冲突）→ 归档进发布 FAQ。

### 3.10 敌我识别（IFF）

- **判定（服务端权威）**：敌友 = 同一 `Faction`；归属只读服务端 `FactionManager`，客户端渲染层仅接收归属结果、禁止本地自判（防伪装/防作弊）。同阵营 = 友，跨阵营 = 敌。
- **视觉呈现（P0）**：
  - 名字标签：Scoreboard Team 的 `color` 染玩家名（vanilla 原生），渲染距离放宽与 §3.9 联动。
  - 头顶阵营三角标：自绘 HUD 标记（可开关），远处小人不渲染时仍可辨敌我。
  - 准星目标 IFF 面板：瞄准实体显示 [名称 / 阵营色 / 血条 / 距离]，友军绿、敌军红、中立灰。
- **命中与友伤（P0）**：允许友伤，但伤害砍半；**按次扣款**：每次命中友军按造成伤害量计罚（如每 1 点伤害罚 $20，数值待平衡），受害队友不收到补偿，客户端警告「友军！」；**友军击杀**：若攻击造成队友死亡 → 受害队友获得补偿（数额待定），攻击者**追加罚款** = 基础罚款 × n（示例 n=2，待平衡）。击杀/赏金只记敌方（`DamageSource` + attacker 归属）。**防刷**：非致命友伤无任何转移收益（受害者无补偿），天然消除互刷动机；击杀补偿需真实击杀，同攻击者对同受害者短时间内仅计首笔。
- **探测联动（P1）**：雷达塔/塔楼探测圈内按阵营标点（敌红点/友蓝点），与标记系统（§3.9）共享同一 IFF 数据源。
- **伪装（P2 不实现）**：不做阵营伪装/套皮机制，保证 IFF 数据源可信。

### 3.11 与 SuperbWarfare 联动（必要附属模组）

- **定位**：本 mod 是 **SuperbWarfare（SBW）的必要附属模组** —— 枪械/弹药/护甲/火炮/载具等战斗资产全部由 SBW 提供，本 mod 提供「WARDOGS 玩法层」：三阵营、控制区/Hot Zone、现金经济与配装、FOB 与工事、IFF、计分结算，并与之深度联动。
- **联动点**：
  - 配装商店：购买项直接映射 SBW 物品（含附件/弹药），负重与价格由本 mod 配置。
  - 击杀判定：兼容 SBW 伤害来源（枪械/爆炸/载具）→ 阵营击杀/助攻/赏金。
  - 工事与破坏：本 mod 工事方块带归属与方块破坏保护；与 SBW `explosion_destroy` 配置联动，己方工事不被爆炸直接拆（PvP 走本 mod 破坏伤害）。
  - 载具（P2）：SBW 提供坦克/直升机等，本 mod 做购买/阵营归属/损坏赏金。
- **依赖版本**：SBW NeoForge 1.21.1 线（与基线一致）；其运行时依赖（GeckoLib，及 1.20.1 线所需的 Curios）随 SBW 发布页要求必装。版本定位已定：**1.21.1 基线（1.21.x 向上兼容）**，26.x 待 SBW 跟进后再移植。
- **许可（已定）**：基于 SBW 公开 API 联动、不复制其代码；**公开发布，但禁止未授权二次分发**（自定义许可，参考 SBW 做法；因不复制 GPL 代码，不受 GPL 传染约束，务必守住此红线）。美术资产：枪械/载具资产由 SBW 提供，本 mod 自产 UI/工事/阵营资产，不直接复用于独立分发。
- **弃更/版本锁定风险**：硬依赖 SBW → 锁版本、跟进其更新，必要时 fork 维护（见 03 风险表）。

### 3.12 AI 玩家填充与顶替机制（PvPvE）

- **定位（已定）**：30 人服务器向 + 单机可玩。战局维护每阵营目标人数（默认三方共 30 战斗单位），AI 填补空槽；真人加入 → 顶替一个 AI 槽位（AI 退场，真人正常出生）；真人退出 → AI 补位。单机 = 全 AI 战场，体验与服务器一致。
- **M1 实现形态（已定）**：AI 采用**抽象模拟单位**（服务端纯数据：假 UUID + 模拟坐标），无实体、无渲染，占据阵营槽位并以模拟坐标参与占区计分；真人顶替/退出补位即时生效。**实体化（可见、可击杀的自定义 Mob）延后**到后续里程碑 —— M1 验收只要求「真人顶替 AI 正常生效」，抽象单位即可满足且不引入实体注册/模型/寻路负担。
- **AI 类型**：
  - 阵营 AI：走与真人相同规则（占区、造/拆工事、守 FOB、买装），击杀赏金按真人的 50%（示例，待平衡）。
  - 中立威胁（可选 PvE 层）：地图野区 AI 单位，击杀给少量现金（数值待定）。
- **行为实现**：目标驱动状态机（占区 → 交火 → 补给 → 回防）；不做全图逐 tick 寻路 —— 惰性 tick：仅激活区块附近 / 交战中的 AI 高频决策，其余低频（2~4 tick/次）。
- **顶替与同步**：顶替由服务端执行（删 AI 实体 → 播报「AI 被玩家顶替」→ 真人出生）；AI 移动/开火走服务端模拟，客户端仅渲染，不新增自定义网络协议。
- **性能约束**：AI 上限 = 目标人数 − 当前真人；AI 射击与真人共享抛射物限流（§3.8）。

## 5. 数据流与网络协议草案

- `C2S`：请求购买（id/count）→ `FactionSelect` → `PlaceFort` → `TowerInteract` → `TeamDeposit`。
- `S2C`：`SyncFaction`（加入时）→ `SyncCash`（附体）→ `MatchState`（2s 周期：三阵营分数/区状态）→ `ZoneSettle`（结算动画/广播）→ `KillFeed` → `FortState`（耐久变化）。
- 所有变更先过服务端校验，客户端仅呈现；关键操作带冷却与频率限制。

## 6. 存档与安全

- 对局数据：`SavedData` 持久化（阵营分数、金库、FOB 位置、塔楼码字）。
- 账号解锁：独立 `UnlockData`（按玩家 UUID）。
- 防作弊底线：现金/金库/建造全服务端权威；投射物伤害归属走 `DamageSource` + attacker 判定；禁传送/飞行外挂依赖服务端位置校验（P1）。

## 7. 迁移 26.x 注意事项（若选新版）

- 版本号体系变 `26.1.0.x-beta`；去混淆 → 官方参数名可见，删 Parchment 可选。
- Java 25 + Gradle 9.1+；`ItemStackTemplate` 取代数据文件里的空 ItemStack；`GuiGraphics` 重构。
- 生态尚未全量跟进（第三方库滞后风险），故基线推荐 1.21.1，26.x 作为 v1.1 移植目标。

## 8. 测试策略

- Datagen：方块/物品模型、语言、标签、战局配置 JSON（版本无关校验）。
- 冒烟测试：单机快速开局 → 阵营分配 → 占区结算 → 购买/建造/破坏 → 结算界面全链路。
- 联机测试清单：2 人同队占区、跨维度边界、区块卸载时结算、网络断连重连后的附体恢复。
- 性能压测：30 假玩家 + AI 满槽脚本（测试专用命令）观察 TPS/网络包量。
