## 3. 关键系统设计

### 3.1 阵营与队伍
- `Faction` 枚举（LONESTAR/VALKYRA/MANTICORE/NONE）+ 服务端同步的 `FactionManager`；枚举携带四项阵营增益字段（人力/火力/补给/上限，取值 0~5，当前**先只做展示与数据结构、暂不接实际效果**，界面已标注「预览」）。
- 阵营增益（开局选择界面展示，`Faction.getManpower/getFirepower/getSupply/getCap`）：红 LONESTAR 人力5/火力5/补给3/上限2；蓝 VALKYRA 人力2/火力4/补给5/上限4；绿 MANTICORE 人力4/火力3/补给3/上限5。
- 计分板队伍承载：名字染色、友伤开关、Tab 排序。阵营经 `FactionAttachments` 附体持久化（`copyOnDeath`，跨重连/死亡保持）。
- **加入不再自动分配**（2026-10-03 开局流程）：登录时无阵营玩家保持 `NONE`，由「雇佣兵手册」开局选择阵营（见 §3.14）；已有阵营则恢复计分板队伍并下发 `SyncFaction`。原「加入即 `leastPopulated` 自动平衡」与「每 30s 人数最少方 1.1x 赏金系数」为早期设想，**未实现**（`leastPopulated`/`countRealPlayers` 已随开局流程删除）。

### 3.2 控制区 / Hot Zone（服务端权威）
- `ControlZone`：圆心坐标 + 半径 + 归属性 + 冷却计时；`ServerTickHandler` 驱动 30s 结算。控制区半径为 **512 方块级**（`Config.CONTROL_ZONE_RADIUS` 默认 256，可配 16~512；圆心 = 主世界出生点）。
- 计数规则：结算瞬间取圈内存活玩家按阵营聚合，Hot Zone 内 ×2 权重。
- **区块未加载问题（重要）**：控制区可能落在未加载区块 → 设计为「逻辑区」而非依赖实体扫描：用玩家坐标查询（即使区块卸载，玩家所在区块必加载），并以 `SectionPos` 圈内坐标判定，避免全图 chunk 强制加载。结算若 0 人在圈 → 不加分。
- Hot Zone 每 45s 迁移：在控制区内取随机点，倾向人数劣势侧。

### 3.3 塔楼与钻井台
- 塔楼 = 方块 + BlockEntity：交互出码字（服务端生成，客户端展示）、码字进度存储于队伍数据。
- 钻井台 = BlockEntity 运行态：燃料（物品）随时间消耗，生效期间每 tick 把控制区圆心向 FOB 偏移；全图广播提示。

### 3.4 经济与配装
- 现金：`DataAttachment`（int）挂 `ServerPlayer`，仅服务端可改；同步走附体同步。
- 交易服务 `EconomyService`：`trySpend(player, cost)` / `pay(player, amount, reason)`，统一走日志与防外挂校验。
- 配装：背包内物品带 `DataComponent`（负重、属性）。负重由服务端累计，超阈值给移速/跳跃修正（AttributeModifier）。
- 死亡（口径以 §3.4 M2 落地段为准，2026-09-30 决策）：阵营玩家死亡**不产生地面掉落**——被敌方击杀时装备按卖价六折折算为赏金给击杀者，其他死因装备重生原样返还；现金永不丢失（总资产保留、本命收入清零）；保险券（P1）预留。

**M2 落地状态（2026-10-01，配装商店与负重 ✅ 已实现；详设 `.trae/documents/m2-shop-design.md`）**：
- 现金复用 M1 `PlayerWallet` + `WalletAttachments`（服务端权威，`WalletPayload` 单发本人）；`PlayerWallet` 扩展为 `{spent, total, earned}`——**HUD 顶栏左值 = 本条命赚到的钱**（击杀/占区等战斗收益累计，商店买卖不计入，死亡清零；总资产跨死亡保留，附体加 `copyOnDeath`）；
- 交易 `ShopManager`（BUY/SELL/TAKE/STORE，服务端全量校验、不信任客户端价格）+ 目录 `data/msb/shop/<category>.json`（`SimpleJsonResourceReloadListener` 加载，`OnDatapackSyncEvent` 在 join/`/reload` 时下发 `ShopDataPayload`；协议版本升至 2）；
- 配装：个人**储存格**（`ShopStorage` per-player 附体，`copyOnDeath`，默认 60 叠）——**购买入库带「绿框 = 无损卖回 100%」**（`refund` 计数），取出到玩家栏即失效、玩家物品存入不获得；卖出按「无损 + 其余六折」混算；
- 负重 `WeightService`：目录内物品计重（储存格不计），60% 起线性减速、100% 达 `weightSpeedPenaltyMax`（默认 -20% 移速）并下调跳跃；**取回受负重上限约束**，购买不受限（先入储存格）；
- 界面 `ShopScreen`（B 键开关，GuiGraphics 自绘四区：分类栏 / 商品 6 列滚动格 + 购买·出售面板 + 储存格 5 列滚动格 / 玩家背包映射）；
- 死亡：阵营玩家**不产生地面掉落**（`LivingDropsEvent` 拦截本阵营玩家掉落）——被敌方击杀时 41 格装备按卖价六折折算为赏金给击杀者、重生不返还；其他死因装备重生原样返还；现金与储存格保留（保险券 P1）。

### 3.5 建造与破坏
- 工事方块：自定义 `Block`（mapColor/破坏时间/硬度），绑定耐久 `BlockEntity`；PvP 破坏走专用伤害事件（区分玩家/环境），归属队伍记录在方块附体。
- 建造权限：仅 FOB 一定半径内可放置；放置时从队伍金库扣费（金库 = 队伍侧账户，见 §3.6）。
- 摧毁结算：按工事等级给击杀者/队伍发赏金；己方拆除回收 50%。

### 3.6 队伍金库与服务器侧账户
- 工事/塔楼费用从**队伍金库**扣，个人现金可向金库转账（WARDOGS 的团队经济感）。金库 = 服务端 `TeamAccount` 数据。

### 3.7 HUD 与菜单（UI 技术选型）

- **P0 默认：NeoForge 原生 `GuiGraphics` / `Screen` 自绘** —— HUD 覆盖层与全部菜单（阵营选择/配装商店/建造目录）用原生渲染 API 实现，零额外 UI 依赖；原型 tech-dark 视觉稿（矩形贴图/等宽字体）原生即可还原，无需重 UI 框架。
- HUD 覆盖层（客户端）：计分板（三方分数/进度条）、30s 结算倒计时、Hot Zone 圈内标记、现金、负重条、击杀流。全部走 `RenderGuiEvent`/自定义 HUD 类，配置项可开关。
- **可选增强（按需引入，不进 P0 核心）**：
  - Cloth Config API：Mod 设置页（实体距离引导、HUD 开关、键位）。
  - JEI：物品图鉴 / 商店物品展示（玩家友好）。
  - Patchouli：玩法手册 / 教程文档。
  - 3D 展示：GeckoLib 动画模型在商店/结算界面做武器/工事预览（P1，随动画实体立项）。
- **明确排除**：ImGui / CEF / HTML 等重 UI 框架 —— 与 MC 渲染管线冲突、包体积大、HUD 帧率差，本项目无此需求。
- **性能**：HUD 元素缓存布局与纹理（避免每帧字符串布局/分配）；世界空间标记（IFF 三角标、标记点、Hot Zone 圈）用批量 quad 绘制、不做每帧实体遍历；所有 HUD 元素可开关。

### 3.8 性能（30 人 + AI 等效 60~80 战斗单位）
- 避免每 tick 全图实体扫描；控制区用坐标判定。
- 抛射物限流（每玩家每秒投射物数上限），粒子/音效客户端节流。
- 网络节流：位置类高频包用 `Entity` 原生同步；自定义状态包降频（≥2 tick 间隔）。
- 推荐服务端：Paper 化优化不适用（NeoForge），用性能向 mod 组合（见 03 文档「配套性能 mod」）。

### 3.9 远距玩家渲染与可见性（Known Issue）

- **现象**：大地图战场上，视距内的远处玩家不渲染 → 狙击、侦察、控局判断受损（WARDOGS 核心体验的一部分）。
- **根因（三类）**：
  1. 客户端「实体距离」（Entity Distance，1.19.3+）滑块低于区块视距，实体按模拟距离比例被裁剪。
  2. 第三方性能 mod（EntityCulling / 实体剔除类）做视锥 + 遮挡剔除，远处玩家实体被剔除。
  3. 服务端 simulation distance 与客户端 render distance 不匹配：远端玩家所在区块客户端未加载 → 不渲染（属渲染距离外，体验同源）。
- **解决与缓解**：
  - **P0 配置引导**：Mod 启动时引导「实体距离 = 最大」；检测到 EntityCulling 类 mod 时提示把玩家实体加入剔除白名单（发布页 FAQ 写入兼容矩阵）。
  - **P0 视觉兜底**：对玩家实体放宽名字标签渲染距离 + 阵营染色标签 —— 即使小人未渲染也能定位。
  - **P1 玩法替代（推荐，符合 WARDOGS）**：标记系统（快捷键标记敌方位置，标记点全图可见、持续 N 秒）+ 雷达塔/塔楼区域探测圈 —— 远距交战不依赖像素级渲染。
  - **P1 渲染兜底**：Mixin 对玩家实体豁免视锥剔除并设距离分级（远距降为名称标记/低模），仅玩家数超阈值时启用分级。
  - **兼容矩阵**：Sodium/Embeddium（分级渲染）、EntityCulling（白名单）、FerriteCore（无冲突）→ 归档进发布 FAQ。
- **战术地图（M1 落地，已定；2026-09-29 变更：移除 Xaero 集成，回归自绘增强版）**：**M 键开关自绘全屏 TacticalMapScreen**（打开时再按一次关闭，GuiGraphics 渲染，符合 §3.7 原生 UI 原则），**不集成任何第三方地图**（Xaero 方案已废弃：版本门/mixin 脆弱性/waypoint 平台限制收益不匹配，代码与依赖已全部移除）。
  - **增强功能（2026-09-29）**：① 缩放——滚轮 + **右侧竖向缩放条**（对数刻度，顶部=最大放大/底部=最小缩小，点击/拖动改变缩放并可视化当前倍率百分比），默认整图适配，范围 10%~24×；② 平移——左/中键拖动（拖动即自动切自由视角）；③ 跟随/自由——右下角「我」按钮切换（跟随=镜头锁定玩家）；④ 朝向旋转——地图随玩家视角旋转、箭头恒指前，右上角 **Lock 按钮**锁定北向（上北下南左西右东，切换写回配置 `tacticalMapRotateWithPlayer`，默认随配置）；⑤ 左下角 **4 向罗盘**（N 红 / E·S·W 白，随地图旋转联动，等待对局数据时也始终显示）；⑥ 单位标注——友 T / 敌 E / 未分配 ? + 距玩家格数；⑦ 悬停单位工具条（阵营/距离/交战状态）；⑧ 光标右侧实时世界 XZ 坐标 + 距玩家距离；⑨ 图例（左上）+ 顶部对局栏（倒计时/三方分数）；⑩ 右下角按钮——圈居中（镜头移向控制区中心并切自由）/ 我（跟随-自由切换），我或圈中心不在屏幕内时在屏幕边缘显示「我/圈 + 距离」指示器（沿中心方向等比投影到屏幕边缘）；⑪ 距离网格——小块=1 区块（16 格，与 F3+H 区块边界同步），大块=4×4 区块（64 格）粗线，**超大块=每级是上级的 4×4（16×16 区块 = 256 格）**，**特大块=超大块的 2×2（32×32 区块 = 1024 格）始终粗线兜底**；**两级稀疏（防网格过密）：缩小到 99% 时隐藏小块线、大块线降为小块样式，缩小到 35% 时再隐藏大块线、超大块线降为小块样式**；网格线随地图旋转/平移/缩放，每条线经 PoseStack 旋转后单次 fill 矩形绘制（每条线恒定 1 次 drawCall，性能与视野无关）；⑫ **圆环渲染**——地图边界圆/控制区圆由**纯白环贴图（`textures/gui/ring.png`，512×512 RGBA，外沿贴边）blit tint 上色**：1.21.1 无带 tint 的 GUI blit，走 `DefaultVertexFormat.POSITION_TEX_COLOR` + `GameRenderer::getPositionTexColorShader` 手动提交带顶点色 quad（顶点色即 tint，半透明可控），环宽随屏幕半径等比缩放（整图适配时约 2~4px，放大变粗、缩小变细），单次 drawCall、性能与视野无关；⑬ **创造传送（2026-09-29）**——按 **T 键**传送到光标所指地面柱的最高方块上：客户端仅发送目标 XZ（`TeleportRequestPayload` C2S），服务端校验创造模式（`instabuild`）后自顶向下扫描该列求「最高可站立方块」Y 并 `teleportTo`（客户端不可指定 Y，防作弊）；世界边界外或区块未加载时拒绝并提示「Teleport failed: target unreachable」（避免强制生成地形/落到基岩层）；非创造模式按 T 弹出提示「Teleport (T): Creative only」；基地坐标经 `BaseData`（SavedData，存主世界）持久化——重进存档后 MatchManager.init 恢复基地安全区，registerBase/removeBase 均写盘。
  - **数据源（服务端权威）**：由服务端按已激活/交战区高频广播单位列表（可并入 MatchState 或独立 UnitPositions S2C 载荷），客户端仅渲染不推断；广播频率与 AI 惰性 tick 同频，远离激活区的单位不推送细节（符合 §3.12 性能约定）。
  - **显示内容（M1 四类）**：① 对局信息——控制区（圆/半径/倒计时）、三方得分；② 友军与 AI 单位——本方阵营玩家 + 全部 AI 模拟单位位置（阵营点）；③ 世界点位——出生点、地图边界（塔楼/锚点随 M4 加入）；④ 敌方单位——**仅已交战敌方单位 + 敌方 AI 位置**，隐蔽敌人不显示。
  - **敌情可见性规则**：交战状态由**服务端判定**（最近 N 秒内造成/受到伤害即标为交战，数值待平衡），客户端禁止本地推断（防作弊，与 §3.10 IFF 同源）。P1 雷达塔/塔楼探测圈（§3.10 探测联动）接入后，圈内敌情同样落点，与标记系统共享数据源。
  - **IFF 配色**：友蓝 / 敌红 / 中灰（与 §3.10 视觉一致）；数据来自服务端归属，不本地自判。
  - **坐标映射（线性可逆变换，旋转/固定共用）**：世界格 → 屏幕像素 `sx = cx + (dx·cos−dz·sin)·s / sy = cy −(dx·sin+dz·cos)·s`（旋转模式 θ=−yaw 使视线前方指上）；固定北向 `sx = cx + dx·s / sy = cy + dz·s`；逆变换供拖拽平移与光标坐标读取共用。玩家朝向箭头由世界前向向量经同一变换映射（旋转模式恒指上、固定模式按 yaw 指向）。圆环渲染依赖纯白环贴图（见 ⑫），随屏幕半径等比缩放，放大/缩小均不失真。

### 3.10 敌我识别（IFF）

- **判定（服务端权威）**：敌友 = 同一 `Faction`；归属只读服务端 `FactionManager`，客户端渲染层仅接收归属结果、禁止本地自判（防伪装/防作弊）。同阵营 = 友，跨阵营 = 敌。
- **视觉呈现（P0）**：
  - 名字标签：Scoreboard Team 的 `color` 染玩家名（vanilla 原生），渲染距离放宽与 §3.9 联动。
  - 头顶阵营三角标：自绘 HUD 标记（可开关），远处小人不渲染时仍可辨敌我。
  - 准星目标 IFF 面板：瞄准实体显示 [名称 / 阵营色 / 血条 / 距离]，友军绿、敌军红、中立灰。

### 3.12 AI 玩家填充机制（PvPvE；真人顶替已于 2026-10-03 移除）

- **定位（已定）**：30 人服务器向 + 单机可玩。每阵营维护 AI 实体数量 = 该阵营**开局选择的 AI 数量目标**（`FactionSetupData` 持久化，未设置时回退 `Config.AI_TARGET_PER_FACTION`）。**真人玩家独立于 AI 槽位**：真人加入/退出不再顶替或补位 AI（`onRealPlayerJoined`/`onRealPlayerLeft` 已删除），AI 数量不再随真人数增减。单机 = 全 AI 战场，体验与服务器一致。
- **M1 实现形态（已定：实体化，2026-09-30 落地并实测通过）**：AI 为真实 Minecraft 实体 `AiCombatantEntity`（`extends PathfinderMob`，原版 Steve 外观零新增资产，faction 字段 + NBT 持久，`setPersistenceRequired` 不自然消失）。实体经 `AttributeSupplier` 绑定属性（`MAX_HEALTH 20` / `MOVEMENT_SPEED 0.25`，经 `EntityAttributeCreationEvent` 注册，防 NPE）；`getScoreboardName()` 返回 UUID 供计分板 Team 加入（阵营染色 + SBW 敌我判定可用的 `Entity.getTeam()`）；`canBeLeashed=false` 防玩家栓绳带走。生命周期由 `AiManager` 全权管理。
- **AI 类型**：
  - 阵营 AI：走与真人相同规则（占区、造/拆工事、守 FOB、买装），击杀赏金按真人的 50%（示例，待平衡）。
  - 中立威胁（可选 PvE 层）：地图野区 AI 单位，击杀给少量现金（数值待定）。
- **行为实现**：目标驱动状态机（占区 → 交火 → 补给 → 回防）；不做全图逐 tick 寻路 —— 惰性 tick：仅激活区块附近 / 交战中的 AI 高频决策，其余低频（2~4 tick/次）。
- **M1 惰性推进（已落地）**：`AiManager.tick()` 由 `MsbServerEvents.onServerTick()` **单一驱动**（重复调用会破坏 lazyTick 相位）；每 tick 先清理实体——`isDeadOrDying` → 登记复活队列、`isRemoved`（chunk 卸载）→ 直接移除；每 4 tick 对所有在场实体 `updateChunkForced` 钉住所在 chunk（基地方块多在模拟距离 12 区块外，不钉会被卸载清出单位列表）并调 `entity.lazyTick(圆心, 半径)`：圈外 `getNavigation().moveTo(圆心, 0.8)`；**圈内自由巡逻**（到达目标点后随机换圈内新点漫游，8~20s 一次，半径 80%）；非交战状态扫描 5 格内掉落物并**主动走过去拾入战利品容器**（优先于巡逻/推进）。
- **AI 战斗逻辑（已落地，2026-09-30）**：自研 `AiGunShootGoal` 替代 SBW `GunShootGoal`（仅调用 SBW 公开 API：`GunData.tick/canShoot/shoot/startReload/startBolt`，不复制其代码）——**40 格内锁定压制**（索敌范围 `FOLLOW_RANGE 48` 覆盖）、**>30 格边逼近边压制（1 秒 1 发）、≤30 格站定按武器 RPM 全速扫射**（按真实欧氏距离分档；SBW 原 goal 误用平方距离、实际阈值等效仅 5.5 格）；瞄准参数（`AimTime`/`Spread`/`Zoom`）读 `data/msb/sbw/mob_guns/ai_combatant.json`，`Spread=8` 控制 AI 射击夹角（弱于玩家 ADS）。
  - **行为增强**：攻击非中立生物（`Enemy` 接口，僵尸/骷髅/灾厄等）；受击立刻锁定攻击者并通知半径 8 格同阵营 AI 一并索敌（`retaliate`，同阵营误伤不触发）；射击射线夹角（横向 1.5 格）内有同阵营单位时停火并后撤避让，拉开 5 格以上后恢复；换弹真空期全速与目标拉开距离。
  - **开火表现**：交战期间经 `DATA_AIMING`（SynchedEntityData）同步，客户端 `AiCombatantModel` 双臂端平、随视线抬起（骷髅射手同款姿势）；AI 换弹音效按用户要求已移除（最终为静默）。
- **AI 双容器与掉落（已落地，2026-09-30）**：**装备容器 27 格**（初始副武器 glock_17 + 手枪弹/步枪弹）与**战利品容器 27 格**（主动拾取的掉落物，`ItemStack` 自动堆叠）；死亡掉落——**战利品容器始终掉落**，装备容器 + 主手武器由指令 **`/MSBS AIpmc drop t|f`**（OP 权限 2）控制，默认 `f` 不掉（`Config.AI_DROP_LOOT` 写盘持久化）；主手先摘除再走原版流程（防原版装备掉落叠加成两把）。
- **击杀与复活（已落地）**：AI 被击杀 → 阵营独立复活队列（`respawnQueue` FIFO，`RESPAWN_CD_TICKS=200` = 10s）；CD 到期从所属阵营基地方块周围 ±6 格复活（站方块顶面）；**无基地不生成/不复活**（`reconcile`/`drainRespawns` 前置检查基地存在，基地方块放置 `onBasePlaced` 立即补足）。
- **存档幽灵清理（已落地）**：`setPersistenceRequired` + seq 每会话重置 → 旧存档残留 AI 与本次单位重名造成计数/观感混乱；`AiManager` 构造时 `purgeStaleUnits()` 遍历主世界清除全部残留 AI（先 `removePlayerFromTeam` 再 `discard`）。
- **目标数量与同步（2026-10-03 更新）**：`AiManager.reconcile(faction)` 目标 = `FactionSetupData.getTarget(faction)`（开局选择写入，首写固定）；AI 数量**不随真人增减**，真人加入不再顶替 AI。基地放置（`onBasePlaced`）→ `reconcile` 补足到目标人数；AI 移动/开火走服务端模拟，客户端仅渲染，不新增自定义网络协议。原「顶替播报」语言键 `msb.chat.ai_replaced` 已随机制移除。
- **性能约束**：每阵营 AI 上限 = 开局选择的 AI 数量（5~15）；AI 射击与真人共享抛射物限流（§3.8）。
- **排障记录（2026-09-30 M1 推进链路）**：① lazyTick 诊断门控若用 `level().getGameTime() % 100` 会与 `tickCounter % 4` 相位错位 → 日志永不打印（假阴性），统一由 AiManager 传 tickCounter 门控；② 单位批量消失且不复活 = 所在 chunk 卸载（`isRemoved` 直接移除不登记）→ 每 4 tick 重钉 chunk + 探针分离 deadRm/unloadedRm；③ 修复后实测验证推进 / 不消失 / 复活 / 进圈四项全部通过；该批诊断探针已清理。
- **排障记录（2026-09-30 战斗链路）**：① mob_guns 数据 key = `EntityType.getKey()` 全名（`msb:ai_combatant`）→ 文件须放 `data/msb/sbw/mob_guns/`（SBW 监听器跨 namespace 遍历），且 `Data` 需 `GunData` 子层包裹（`TagDataParser` 直接 merge 到 CUSTOM_DATA 根，层级错则弹药读为 0）；② `GunData.save()` 有 nbtVersion fast-path 且 `invalidateState()` 全库零调用 → 弹药改动不会落盘，**必须手动 `stack.set(CUSTOM_DATA, CustomData.of(data.tag()))` 写回**；`DATA_CACHE` 为 weakKeys+weakValues，缓存失效即从 NBT 重读（不写回则 AI 弹尽不开火）；③ 自研 goal 的 `canUse` 必须先调 `MobGunData.getGunData()`（选枪初始化 `selectedData`），否则 `aimTime()/spread()` 空指针崩服；④ 主手掉落需先摘除（`setItemInHand EMPTY`）再调 `super.dropAllDeathLoot`，否则与原版装备掉落叠加成两把主武器；⑤ SBW 音效播放函数对非玩家直接 return（`shooter !is ServerPlayer`），实体绑定音效需 `ClientboundSoundEntityPacket` + `ChunkMap.broadcastAndSend`（该包非 `CustomPacketPayload`，不能走 `PacketDistributor`）；⑥ 战斗链路临时探针（equip/probe）**已清理**（当前源码无探针残留）。
- **AI 装备（已落地，2026-09-30）**：三阵营基础装备——红 LONESTAR `superbwarfare:hk_416` / 蓝 VALKYRA `ak_12` / 绿 MANTICORE `m_4`（仅引用 SBW 公开注册名）+ 副武器 `glock_17` + 弹药物品 `rifle_ammo`/`handgun_ammo`（入装备容器）；主手枪以 `GunData.virtualAmmo=512` 供弹（非玩家实体无物品栏，mob 射击全靠虚拟弹药；打光后射击 goal 自动停止、退化为只巡逻/推进）。装备不产生经济收支——AI 不消耗现金，纯粹是战斗表现层。

### 3.13 阵营基地方块（安全区，PRD §5.1）✅已实现（M1，2026-09-29）

- **基地方块**：三阵营各一个方块，**不自动放置**——由玩家手动放置 `base_block_*` 方块触发注册（`BlockEvent.EntityPlaceEvent` → `MatchManager.registerBase`，以方块坐标 `(x, y, z)` 为中心；重复放置覆盖该阵营基地），拆毁（`BlockEvent.BreakEvent` → `removeBase`）即安全区失效。方块实体 `BaseBlock` 三实例（`base_block_lonestar/valkyra/manticore`）随 `DeferredBlock`/`DeferredItem` 注册，datagen 生成 blockstate/模型（复用红/蓝/绿羊毛贴图）/掉落表（`dropSelf`）。符合 PRD「基地由玩家建立」定位。
- **判定（服务端权威）**：伤害入点 → `LivingIncomingDamageEvent`（伤害序列最前）服务端判定：受害者在己方基地方块 XZ 平面半径 16（`Config.BASE_RADIUS`）内 → `event.setCanceled(true)`（21.1.252 的 `LivingDamageEvent.Pre` 不可取消，故用该事件）。玩家与 SBW 载具共用入口；判定**只比较坐标**（复用 `ControlZone.containsXZ`），不依赖实体扫描（对齐 §3.2 逻辑区思路，免区块强制加载）。
- **数据**：基地坐标（x,z,y 三阵营各一份）随 MatchState 广播（`basePositions[]`，-1 表示未放置）；客户端仅用于战术地图显示（`drawBases` 阵营色方点 + 「B」），无敌由服务端强制。
- **载具（SBW 提供）**：区内本方载具（骑乘玩家阵营归属）同样无敌（`LivingIncomingDamageEvent` 取消）；**缓慢恢复**：MatchManager tick 内每 `BASE_REGEN_INTERVAL_SECONDS`（默认 2s）对区内本方 LivingEntity 载具 `heal(1.0F)`；非 LivingEntity 载具的恢复延后到载具接入里程碑（TODO）。识别仅用注册名 namespace `superbwarfare`（`BuiltInRegistries.ENTITY_TYPE`），不 import SBW 类，遵守红线。
- **玩家死亡基地复活（已落地，2026-09-30）**：`PlayerEvent.PlayerRespawnEvent` → 玩家有阵营且已放置该阵营基地时，`teleportTo` 到基地方块**上方 1 格**（主世界，跨维度死亡一并传送）；无阵营 / 未放置基地则维持原版出生点（床/世界出生点）。复活顺序安全：`Clone` 事件先复制阵营附体，`Respawn` 事件读取阵营后覆盖重生位置。
- **放置约束（2026-10-04 决策 ✅已实现）**：基地方块**不可放入控制区圆内**（防「圈内无敌区」）——`onBaseBlockPlaced` 内以 `MatchManager.getZone().containsXZ(pos)` 校验，违规取消放置并提示 `msb.base.in_zone`；同阵营基地间距等其余约束留待 M3 与 FOB 体系一并设计。

### 3.14 开局流程与雇佣兵手册（2026-10-03 ✅已实现）

流程：**进入世界（无阵营）→ 自动获得「雇佣兵手册」→ 右键打开手册选择阵营/资金/AI 数量 → 传送到所选阵营基地 → 开始游戏**。

- **手册物品**：`MercenaryHandbookItem`（`msb:mercenary_handbook`，创造标签可见，模型复用原版 `item/book` 贴图）。右键 → 服务端下发 S2C `HandbookOpenPayload` → 客户端打开 `HandbookScreen`；服务端权威，手册不消耗（保留承载后续教程）。
- **发放**：`MsbServerEvents.onPlayerLoggedIn` 中，`FactionManager.assignOnJoin` 后若阵营为 `NONE` → `OnboardingManager.ensureHandbook(player)`（背包无手册则补发，放不下掉脚下）并提示 `msb.handbook.granted`。重生 `onPlayerRespawn` 时若仍无阵营 → 再次补发（防死亡丢失）。
- **手册界面 `HandbookScreen`（自绘）**：三张阵营卡（阵营色 + 缩写 + 人力/火力/补给/上限 5 段 pip，数据源 `Faction` 增益字段，顶部标注「预览」）；初始资金三档按钮；初始 AI 数量 −/+ 步进（5~15）；基地状态行（读 `ClientMatchState.getMatchState().basePositions()`，-1 → 显示「无基地配置」）；「确认加入」提交 `FactionSelectPayload`。已开局玩家再开手册 → 显示教程占位页（预留）。
- **资金档位 `FundingTier`**（与 AI 数量**相互独立**）：`TIER_LOW` 3000$ / 击杀收益 ×1.5；`TIER_MID` 8000$ / ×1.0；`TIER_HIGH` 20000$ / ×0.8。**初始资金越高，后续击杀收益倍率越低**。
- **服务端落地 `OnboardingManager.applyChoice(player, factionId, tierId, aiCount)`**：① `setPlayerFaction`（含 `SyncFaction`）→ ② 设 `PlayerWallet(0, tier.money(), 0)` 并下发 `WalletPayload`（总资产 = 档位资金，本命收入/花销清零）→ ③ 写 `MercenaryProfile`（资金档位 + 击杀倍率 ×100 + AI 数量，附体 `copyOnDeath`）→ ④ `FactionSetupData.setTargetIfAbsent(faction, ai)`，若 `allChosen()` 则 `MatchManager.startMatch()` 正式开局（否则等待其余阵营）→ ⑤ 有基地则 `teleportTo` 基地上方 1 格，无基地下发 `msb.onboarding.no_base` 提示并跳过传送。校验：非法阵营忽略、已开局忽略、AI 数量钳制 `[5,15]`。
- **击杀收益倍率**：`MsbServerEvents.settlePlayerKill` 对**正奖励**乘 `MercenaryProfile.killMultiplier()` 后取整（友军罚款负数不缩放；经验值不受影响）。
- **持久化 `FactionSetupData`**（`SavedData`，主世界，key `msb_faction_setup`）：三阵营**各自独立**的「开局 AI 目标数量」，由**首个选择该阵营的玩家写入**（后来者不覆盖）；未设置回退 `Config.AI_TARGET_PER_FACTION`（兜底默认值）。
- **开局门槛与指令（2026-10-04 决策，✅已实现）**：三阵营**均确认 AI 数量后**方可开始对局（门槛达成前 AI 生成与控制区计分不激活，`MatchManager.started` 门控 `reconcile`/结算倒计时）；OP 可用 **`/MSBS game start`** 强制开始——未选择的阵营自动取**最大 AI 数量（15）**（`/MSBS` 权限 2）。
- **队伍指挥（暂定 M3）**：**首个选择某阵营的玩家**成为该阵营指挥官，后续可经**投票或转让**变更；`FactionSetupData` 的跨局重置时机随 M3 指挥/对局体系一并确定（本次决策未覆盖）。
- **Tab 信息栏 `InfoScreen`（预留骨架，2026-10-03）**：Tab 键开关（`MsbKeyMappings.INFO_KEY` + `MsbClientEvents` toggle）；页签 阵营 / 战绩 / 队伍 / 教程——阵营页显示本人阵营与四项增益，其余为占位行待后续填充。打开自绘界面后 `mc.screen != null` 会压制原版玩家列表（与原版 Tab 同键的取舍，已接受）。

## 5. 数据流与网络协议草案

- `C2S`：请求购买（id/count，M2 已实现 `ShopTrade`）→ **`FactionSelect`（开局阵营/资金档位/AI 数量，M1 开局流程已实现）** → `PlaceFort` → `TowerInteract` → `TeamDeposit`。
- `S2C`：`SyncFaction`（加入/改派时）→ `Wallet`（M2 现金）→ `ShopData`/`ShopStorage`/`ShopResult`（M2 商店）→ `MatchState`（1s 周期：三阵营分数/区状态/基地坐标）→ `UnitPositions`（4 tick 战术地图单位）→ `KillFeed` → 结算广播 → `FortState`（耐久变化）→ **`HandbookOpen`（M1 开局流程：右键手册）**。
- 协议版本（`MsbNetwork.PROTOCOL_VERSION`）：**当前为 4**（客户端/服务端须同版本）。历史：M1 初版 1 → M2 商店 2 → 其后每次载荷扩展递增（3 未单独留档；该值仅作握手标识，跳号不影响兼容）。
- 所有变更先过服务端校验，客户端仅呈现；关键操作带冷却与频率限制。
- 已实现载荷清单见各系统小节（§3.1/§3.4/§3.9/§3.12/§3.14）。

## 6. 存档与安全

- 对局数据：`SavedData` 持久化（阵营分数、金库、FOB 位置、塔楼码字）。
- 账号解锁：独立 `UnlockData`（按玩家 UUID）。
- 防作弊底线：现金/金库/建造全服务端权威；投射物伤害归属走 `DamageSource` + attacker 判定；禁传送/飞行外挂依赖服务端位置校验（P1）。
