# 版本定位与里程碑计划

**状态**：版本定位**已定**——**1.21.1 基线**（2026-09-28 用户确认冻结）。本文决策表 A 行为发布基线，B 行不采用，C 行保留为 v1.1+ 移植目标。

---

## 1. 版本定位决策表（2026-09 现状）

| 选项 | MC 版本 | NeoForge | Java/Gradle | 生态 | 结论 |
|---|---|---|---|---|---|
| A（已冻结基线） | **1.21.1** | 21.1.x（稳定） | Java 21 / Gradle 9.x | 16000+ mod、第三方库最全、教程与集成包最多 | ✅ 起步首选，风险最低；**2026-09-28 确认冻结** |
| B | 1.21.11 | 21.11.x | Java 21 | 最后一代 1.x 版本号；生态尚可 | 无显著优势，不做首选 |
| C（未来目标） | 26.1 / 26.2 | 26.1.x（beta→stable） | **Java 25** / Gradle 9.1+ | 去混淆+官方参数名、新版本号体系；第三方库跟进中 | ⭐ 趋势，但生态未全量跟进，建议 v1.1 再迁 |

**推荐**：**A 起步（1.21.1 / NeoForge 21.1.x / Java 21）**，成熟期按「26.x 移植路线」推进（见技术文档 §7 差异清单）。理由：玩法 Mod 的成功更依赖库生态与玩家基数，1.21.1 目前仍是 NeoForge 装机量最大的版本。

> 决策方式：**本决策已冻结**（2026-09-28），`gradle.properties` 已锁定 `minecraft_version=1.21.1`、`neo_version=21.1.252`、`loader_version_range=[1,)`；26.x 移植另开版本线跟进（等 SBW 跟进后按 02 §7 执行）。

## 2. 工程脚手架（冻结即建）

- 模板：NeoForge MDG 模板（`neo.gradle`/`moddevgradle` generator）。
- `gradle.properties`：mod_id=msb、mc/neoforge 版本、mappings=official。
- 基础注册：`MOD_TABS`、初始方块/物品/实体占位。
- CI：GitHub Actions + 自动 `build` 产物；版本号 semantic。

## 3. 里程碑

> 依赖关系：M0 → M1 → M2 → M3 → M4 顺序推进（后一里程碑复用前一的基础设施：附体/结算/网络/GUI）；M5 为发布聚合，收口 M1~M4 全部能力。P1+ 为发布后持续扩充，不阻塞主线。

| 里程碑 | 定位（目的一句话） | 验收标准 |
|---|---|---|
| M0 脚手架 | 跑通工具链与工程基线，扫清环境风险 | `gradlew build` 通过；单机进游戏看到自定义物品栏 |
| M1 阵营与计分 | 搭起 PvPvE 对局最小骨架（有阵营/目标区/得分/AI 补位/战术地图） | 2 人在圈内计分可见；跨重连保持阵营；真人顶替 AI 正常生效；M 键打开自绘战术地图（增强版：缩放/平移/跟随/朝向旋转/单位标注/图例/光标坐标），显示控制区/友军与 AI 单位/交战敌情/世界点位 |
| M2 经济与配装 | 建立「赚钱→买装→战斗→死亡→再买」经济闭环 | 完整闭环可玩 |
| M3 建造与破坏 | 从「抢圈」扩展到「抢地盘」，引入队伍资源池 | 可造可拆、摧毁敌人工事收到赏金 |
| M4 Hot Zone 与塔楼 | 让目标区「活」起来，打破固定圆心控制 | 热区权重计算正确；集码后可移动控制区 |
| M5 打磨与发布 | 收口成可公开发布的完整体验，压测达标 | 30 人 + AI 满槽压测 TPS≥19；发布页与文档齐全 |
| P1+ | 发布后玩法扩充，不与主线冲突 | 见 PRD §9 |

### 3.1 M0 脚手架（已完成）

**功能**：MDK-1.21-NeoGradle 模板工程；注册骨架（物品/方块/实体占位）；Datagen 跑通（语言资源由 datagen 管理）；客户端/服务端分别可启动。

**目的**：确认工具链（NeoForge 21.1.252 / MC 1.21.1 / Java 21）与完整依赖链（SBW + KFF 语言提供器 + SBW JarJar 内嵌的 geckolib 等）在 dev 环境跑通，把环境坑（IPv6 超时、Kotlin 模组加载、Modrinth maven 多加载器文件）在写玩法代码之前全部排掉。

**相关**：02 §1 技术栈、§2 模块划分、§4 依赖矩阵；gradle.properties 冻结基线；§5 风险清单「第三方库版本锁定」；KFF 必须用 5.12.0（Bindings 改名坑）——已记入 project_memory。

### 3.2 M1 阵营与计分（核心已完成；战术地图 2026-09-29 增强完成：M 键回归自绘增强版，已移除 Xaero 集成；基地方块安全区 2026-09-29 完成；AI 实体化 2026-09-30 完成并实测通过——推进/不消失/复活/进圈）

**功能**：Faction 枚举（LONESTAR/VALKYRA/MANTICORE）+ 计分板队伍（阵营染色/友伤开关/Tab）；玩家加入即自动分配（leastPopulated，平局轮询）；阵营经 DataAttachment 持久化（跨重连保持）；控制区（世界出生点圆心、半径可配置）30s 结算计分，0 人在圈不加分；HUD 顶部对局栏（GuiGraphics 自绘，非重 UI 库；全宽顶部条：三方分数阵营色分段整体居中，结算倒计时右对齐仅显示「xx S」）；**全屏战术地图（M 键开关，自绘增强版，见 02 §3.9）**——服务端广播单位列表（与 AI 惰性 tick 同频），显示控制区/三方得分、本方玩家与 AI 单位、出生点与地图边界、敌方单位（仅交战 + 敌方 AI）；支持缩放（滚轮 + 右侧竖向缩放条，10%~24×）/平移（拖动）/跟随与自由切换/地图随视角旋转（可配置关闭）/四级距离网格（小块 1 区块→大块 4×4→超大块 4×4 递增→特大块 2×2 粗线兜底；两级稀疏 ≤99% 隐藏小块/大块变细、≤35% 再隐藏大块/超大块变细）/圆环贴图渲染/单位标注+悬停详情/光标旁实时坐标与距离/图例+顶部对局栏（倒计时/三方分数）+ 基地标记；**不集成任何第三方地图**（Xaero 代码与依赖已全部移除）；AI 实体化单位填充（`AiCombatantEntity`：原版 Steve 外观可击杀、每 4 tick 惰性推进/圈内停止、被击杀后 10s 从所属阵营基地 ±6 格复活、无基地不生成/不复活、存档幽灵启动清理，见 02 §3.12）+ 真人加入顶替 AI 槽 + 真人退出 AI 补位；**阵营基地方块（安全区，见 02 §3.13）**——三阵营方块由玩家手动放置注册（`EntityPlaceEvent`→`registerBase`、拆毁→`removeBase`），不做自动放置；域内本方玩家/SBW 载具免疫伤害（`LivingIncomingDamageEvent` 取消），载具区内缓慢回血，坐标随 MatchState 同步、战术地图图例/标记显示。

**目的**：先让「有阵营、有目标区、有得分、有人（AI 补位）、看得清战场（战术地图）」的对局最小闭环转起来，同时验证五条关键技术路线——服务端权威计分、附体持久化、S2C 网络广播、HUD 自绘、**地图敌情广播与可见性规则**——为后续所有里程碑复用；战术地图同时是 02 §3.9 远距渲染问题的玩法级缓解（远距交战靠地图落点而非像素渲染）。

**相关**：02 §3.1 阵营与队伍、§3.2 控制区（服务端权威）、§3.7 HUD、§3.9 远距渲染与战术地图（已定：自绘增强版，无第三方地图）、§3.10 IFF（敌情/配色同源）、§3.12 AI 填充与顶替；PRD §4 三阵营、§5 对局流程、§6 计分规则；包 faction/match/network/ai/client（战术地图新增 UnitPositions 载荷 + TacticalMapScreen 增强版）；§5 风险清单「区块未加载导致计分失真」的首个缓解点；M2 现金附体直接复用阵营附体模式。

### 3.3 M2 经济与配装

**功能**：现金 DataAttachment（服务端权威，跨重连保持）；击杀/占区结算发钱；配装商店（自绘 Screen）买卖枪械/护甲/消耗品（经 SBW 物品联动）；负重系统（影响移动/跳高，可修正）；死亡丢装规则。

**目的**：把战斗结果转化为经济反馈（PRD §8），形成「赚钱→买装→战斗→死亡→再买」的持久进度，让每局对赌有意义；同时落地友伤规则里的现金扣款/击杀补偿（§3.10 的罚款机制在此兑现）。

**相关**：02 §3.4 经济与配装、§3.6 队伍金库（M2 先做个人现金，队伍池留待 M3）、§3.7 UI、§3.10 友伤罚款与补偿；PRD §8 经济系统；依赖 M1 的附体/结算/网络/GUI 设施；M3 队伍金库在此扩展。

### 3.4 M3 建造与破坏

**功能**：FOB 锚点（队伍领地锚）+ 权限系统（谁可建/可拆）；5 种工事（含耐久、破坏掉落与赏金）；队伍金库（与个人现金并存，供 FOB/工事消耗）。

**目的**：落实 PRD §7 建造破坏对抗，把对局从「抢圈」扩展为「抢地盘」——先占 FOB、再架工事、拆对方 FOB 直接终结据点，形成 M1/M2 之外的第三条胜负轴。

**相关**：02 §3.5 建造与破坏、§3.3 塔楼与钻井台（工事体系同源，部分结构后续演化为塔楼）、§3.6 队伍金库；PRD §7 建造与破坏；复用 M1 的 Team/权限判定与服务端权威结算；§5 风险清单「数值失衡」与「区块未加载」的工事侧缓解。

### 3.5 M4 Hot Zone 与塔楼

**功能**：Hot Zone 迁移机制（目标区按权重/事件切换位置）+ 2 倍计分权重；3~5 座塔楼「集码拉区」（占塔组码后可把控制区中心拉到该处）。

**目的**：落实 PRD §6 动态目标区玩法，打破固定出生点圆心控制的单调性，制造地图争夺焦点；同时用「可迁移目标区 + 塔楼争夺」稀释单一占圈套路，缓解刷分与无敌占区问题。

**相关**：02 §3.2 控制区/Hot Zone（M1 的 ControlZone 需重构为可迁移中心 + 权重模型）、§3.3 塔楼与钻井台；PRD §6 控制区计分规则；§5 风险清单「数值失衡（刷钱/无敌占区）」主要缓解点；依赖 M1 计分结算与 M3 工事耐久体系。

### 3.6 M5 打磨与发布

**功能**：结算界面（战后统计 Screen，含占区时长/击杀/赏金明细）；战绩统计（持久化 K/D 等）；平衡数值表集中配置（控制区半径/权重/赏金/负重阈值等单文件维护）；性能压测（30 假玩家 + AI 满槽）；发布流程（CurseForge/Modrinth 双平台、自定义许可文本、玩法手册类文档）。

**目的**：把 M1~M4 的对局闭环打磨成可公开发布的完整体验；用压测验证 02 §3.8 的 TPS 目标（30 人 + AI 等效 60~80 战斗单位），并为 26.x 移植与平衡调优留下数据基础。

**相关**：02 §3.8 性能、§3.9 远距玩家渲染（标记系统/雷达作为配套体验）、§3.10 IFF、§3.11 SBW 联动与发布许可、§8 测试策略；PRD §9 范围分级；M4 全部能力进入发布基线；风险「大战场帧率」「AI 性能」在此压测收口。

### 3.7 P1+（发布后扩充）

**功能**：钻井台 + 燃料（运营型目标点）；雷达/信标细化（接 02 §3.9 标记系统）；账号解锁（跨服账户解锁枪械/涂装）；保险券（死亡保装备，经济配套）；小地图；**阵营基地方块安全区（半径 16 内本方无敌，见 PRD §5.1 / 02 §3.13）**；**AI 武器装备预设（随 AI 实体化落地，见 02 §3.12）——与 SBW 武器联动、多兵种预设（突击/支援/精确射手/掷弹兵）、服务端自主装备，多套阵容轮换**。

**目的**：发布后的持续玩法扩充（PRD §9 P1/P2 项），丰富长线留存；全部为增量功能，不影响已发布主线，可分批独立上线。

**相关**：02 §3.3 塔楼与钻井台（钻井台燃料）、§3.9 标记/雷达/可见性、§3.6 服务器侧账户；PRD §9 范围分级；M5 发布基线之上增量迭代。

| 大战场帧率/卡顿 | 高 | 坐标判定替代实体扫描、投射物限流、压测脚本（M5） |
