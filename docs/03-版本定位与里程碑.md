# 版本定位与里程碑计划

**状态**：版本定位为**开放决策项**（用户要求先留空）。本文给出决策表与推荐，供确认后冻结。

---

## 1. 版本定位决策表（2026-09 现状）

| 选项 | MC 版本 | NeoForge | Java/Gradle | 生态 | 结论 |
|---|---|---|---|---|---|
| A（推荐基线） | **1.21.1** | 21.1.x（稳定） | Java 21 / Gradle 9.x | 16000+ mod、第三方库最全、教程与集成包最多 | ✅ 起步首选，风险最低 |
| B | 1.21.11 | 21.11.x | Java 21 | 最后一代 1.x 版本号；生态尚可 | 无显著优势，不做首选 |
| C（未来目标） | 26.1 / 26.2 | 26.1.x（beta→stable） | **Java 25** / Gradle 9.1+ | 去混淆+官方参数名、新版本号体系；第三方库跟进中 | ⭐ 趋势，但生态未全量跟进，建议 v1.1 再迁 |

**推荐**：**A 起步（1.21.1 / NeoForge 21.1.x / Java 21）**，成熟期按「26.x 移植路线」推进（见技术文档 §7 差异清单）。理由：玩法 Mod 的成功更依赖库生态与玩家基数，1.21.1 目前仍是 NeoForge 装机量最大的版本。

> 决策方式：本表已固化进文档，确认后在 `gradle.properties` 冻结 `mc_version=1.21.1`、`neoforge_version=21.1.x`。

## 2. 工程脚手架（冻结即建）

- 模板：NeoForge MDG 模板（`neo.gradle`/`moddevgradle` generator）。
- `gradle.properties`：mod_id=msb、mc/neoforge 版本、mappings=official。
- 基础注册：`MOD_TABS`、初始方块/物品/实体占位。
- CI：GitHub Actions + 自动 `build` 产物；版本号 semantic。

## 5. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 大战场帧率/卡顿 | 高 | 坐标判定替代实体扫描、投射物限流、压测脚本（M5） |
| AI 玩家性能/行为失控 | 中 | 惰性 tick + 目标驱动 + AI 数量封顶（真人优先）+ 压测（见 02 §3.12） |
| 区块未加载导致计分失真 | 高 | 控制区逻辑化（§3.2）、结算空圈策略 |
| 第三方库版本锁定 | 中 | 单加载器+少依赖；可选库做「无则降级」 |
| 数值失衡（刷钱/无敌占区） | 中 | 服务端权威+赏金表集中配置+平衡测试局 |
| 若选 26.x 生态滞后 | 中 | 基线定 1.21.1，26.x 走移植路线 |
| 远距玩家不渲染影响狙击/侦察 | 中 | 实体距离引导 + 剔除白名单 + 标记系统（见 02 §3.9） |
| 敌我误判 / 阵营伪装 | 中 | 服务端权威判定 + 友伤按次罚款/击杀补偿（防刷）+ 不做伪装机制（见 02 §3.10） |
| 违规复用 SBW 源码/资产 | 中 | 仅 API 联动不复制代码；公开发布但禁二次分发（自定义许可，见 02 §3.11） |
| SBW 版本锁定 / 弃更 | 中 | 锁版本 + 跟进更新；必要时 fork 维护（见 02 §3.11） |
